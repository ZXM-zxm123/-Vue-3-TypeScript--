# 账单管理系统 - 安全审计清单

## 数据库安全

### 1. 文件权限
```bash
# 设置数据库文件权限为仅所有者读写
chmod 600 bills.db

# 设置数据库目录权限
chmod 700 .
```

### 2. SQLite 安全配置建议
- 启用 WAL 模式：`PRAGMA journal_mode=WAL;`
- 启用 foreign keys：`PRAGMA foreign_keys=ON;`
- 定期备份数据库

### 3. 数据库访问控制
```sql
-- 创建专用数据库用户 (如果使用支持用户的数据库)
-- 对于 SQLite，建议：
-- 1. 数据库文件权限 600
-- 2. 数据库目录权限 700
-- 3. 禁止远程直接访问数据库文件
```

## 加密配置

### 1. 密钥管理
- [ ] ENCRYPTION_KEY 至少 32 个字符
- [ ] 密钥存储在环境变量或密钥管理服务
- [ ] 定期轮换密钥 (建议每 90 天)
- [ ] 密钥泄露后立即更换

### 2. 加密字段
以下敏感字段已加密存储：
- [x] bills.description - 交易描述/商户名
- [x] bills.category - 分类
- [x] accounts.name - 账户名称
- [x] rules.keyword - 分类关键词
- [x] rules.category - 分类

### 3. 金额字段
金额字段 (amount) 未加密，原因：
- 需要支持 SQL 聚合查询 (SUM, AVG 等)
- 用于预算计算和统计
- 如需加密，可考虑结合业务逻辑实现

## 定期审计

### 每日检查
- [ ] 应用日志中的异常错误
- [ ] 失败的登录尝试
- [ ] 异常的 API 请求

### 每月检查
- [ ] 数据库备份是否正常
- [ ] 密钥轮换是否执行
- [ ] 用户权限是否正确

### 每年检查
- [ ] 安全策略更新
- [ ] 加密算法评估 (如迁移到 AES-256-GCM)
- [ ] 完整的安全审计

## 安全事件响应

如果发生数据泄露：
1. 立即更改 ENCRYPTION_KEY
2. 评估泄露范围
3. 通知受影响用户
4. 重新加密所有数据
5. 审查访问日志
6. 报告监管部门 (如需要)
